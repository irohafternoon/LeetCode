計算量
- 時間計算量 O(M * N)  M = N = 100 の時、10^4ステップ　10マイクロ秒と見積もり
- 空間計算量 O(M * N)  

```cpp
#include <vector>

class Solution {
public:
    int uniquePaths(int m, int n) {
    	if (m == 0 || n == 0) {
    		return 0;
    	}
        std::vector<std::vector<int>> coordinate_to_num_paths(m, std::vector<int>(n));
        for (int column = 0; column < n; column++) {
            coordinate_to_num_paths[0][column] = 1;
        }
        for (int row = 0; row < m; row++) {
            coordinate_to_num_paths[row][0] = 1;
        }
        for (int row = 1; row < m; row++) {
            for (int column = 1; column < n; column++) {
                coordinate_to_num_paths[row][column] = coordinate_to_num_paths[row][column - 1] +
                                                       coordinate_to_num_paths[row - 1][column];
            }
        }
        return coordinate_to_num_paths.back().back();
    }
};
```

一番最初に思いついたもの（ただし、math.combの実装について中身を知らない）

```python
import math

class Solution:
    def uniquePaths(self, m: int, n: int) -> int:
    	if m == 0 or n == 0:
    		return 0
        return math.comb(m + n - 2, m - 1)
```

- 以下のコードのようにするとオーバーフローを抑えながら計算できるようだ
- n , k (ただし k > n - kの時　k = n - k) を考えた時
	- 各index i　(1 <= i <= k) について (n + 1 - i) / i を掛けつづけることで計算できる
- 「連続するn数の積は必ずnで割り切れる」ことから各操作で割り切れることが保証される、と理解している
-  n, k がどれくらいの時にint型/long long 型に収まるのか、までは分からなかった。
	- 答えがint型に収まるのであれば、計算途中はlong long 型には収まる気はする
		- よく考えたら (n + 1 - i) / i は　常に1より大きいから計算中の値は単調増加か
		- なので答えがある整数型に収まるなら、計算過程もその型に収まると言えそうだ

```cpp
#include <algorithm>

class Solution {
public:
    int uniquePaths(int m, int n) {
        return Combination(m + n - 2, m - 1);
    }
private:
    long long Combination(int n, int k) {
        if (n < k) {
            return 0;
        }
        if (n == 0 || k == 0) {
            return 1;
        }
        k = std::min(k, n - k);
        long long result = 1;
        for (int i = 1; i <= k; i++) {
            result *= (n - i + 1);
            result /= i;
        }
        return result;
    }
};
```

#### STEP1以外の手法と感想
- 1次元DPで実行する方法もあるが、少し、読み手がわかりづらい気がした（空間計算量が厳しい場合は有効）
	- 空間計算量を削減するなら、更新に必要な箇所が、今見ている行とその１つ前（or１つ先）の行なので、2行だけ作成するのでも良い
	- 上記の方が、STEP1の素直な方法と近く、空間計算量を削減できる

```cpp
#include <algorithm>
#include <vector>

class Solution {
public:
    int uniquePaths(int m, int n) {
    	if (m == 0 || n == 0) {
    		return 0;
    	}
        std::vector<int> column_to_num_paths(n, 1);
        for (int row = 1; row < m; row++) {
        	std::vector<int> column_to_num_paths_next(n);
        	column_to_num_paths_next[0] = 1;
        	for (int column = 1; column < n; column++) {
        		column_to_num_paths_next[column] = column_to_num_paths_next[column - 1]
        										   + column_to_num_paths[column];
        	}
        	std::swap(column_to_num_paths, column_to_num_paths_next);
        }
        return column_to_num_paths.back();
    }
};
```
