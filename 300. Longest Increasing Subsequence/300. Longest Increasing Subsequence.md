# 300. Longest Increasing Subsequence
https://leetcode.com/problems/longest-increasing-subsequence/description/

## STEP1
- 何も見ずに解いてみる

#### 考えたこと
- とりあえず2次元DPでO(N^2)で書けた
- LIS[i][j] = numsのi番目までの文字を使った時、subsequenceの最後がnumsのj番目の時のLIS 
- numのi番目を見た時に、i番目を採用するかしないかの2つの遷移を記述する。
- dp配列の名前はの意味は上記だが、端的にできず「LIS」とあまり意味ないものをつけてしまった。とりあえずコメントで補足しているけど、変数の意味を読み手が覚えておかないといけなるなる点で負荷をかけてしまう

計算量
- 時間計算量 O(N^2) N = 2500 の時 6.25 * 10^6ステップ 6.25ミリ秒と見積もり
- 空間計算量 O(N^2)

 
```cpp
#include <algorithm>
#include <vector>

class Solution {
public:
    int lengthOfLIS(vector<int>& nums) {
        //LIS[i][j] = numsのi番目までの文字を使った時、subsequenceの最後がnumsのj番目の時のLIS 
        // i <= j の時 LIS[i][j] >= 1が保証される
        std::vector<std::vector<int>> LIS(nums.size(), std::vector<int>(nums.size()));
        for (int i = 0; i < nums.size(); i++) {
            for (int j = 0; j <= i; j++) {
                LIS[i][j] = 1;
            }
        }
        for (int i = 0; i < nums.size(); i++) {
            for (int j = 0; j < i; j++) {
                //nums[i]を採用する場合
                if (nums[j] < nums[i]) {
                    LIS[i][i] = std::max(LIS[i][i], LIS[i - 1][j] + 1);
                }
                //nums[i]を採用しない場合
                LIS[i][j] = std::max(LIS[i][j], LIS[i - 1][j]);
            }
        }
        return *std::max_element(LIS.back().begin(), LIS.back().end());
    }
};
```

#### STEP1以外の手法と感想
- 二分探索を用いる手法、セグメント木(もしくはBIT)を用いる方法があり、計算量はNlogNまで削減可能のようだ。
- 
- N^2のDPと比べると二分探索やセグメント木の方が高速だが、N = 2500程度であれば、logの差せいぜい100ミリ秒程度の差しかない
- 入力が非常に大きくなることが想定されるなら、ニ分探索やセグメント木を使用し、そうでないなら分かりやすいDPにしようかな
    - ただし、ニ分探索の手法はLISの復元ができるため、要求される可能性があるのならばニ分探索がよい

1次元DP

```cpp
#include <algorithm>
#include <vector>

class Solution {
public:
    int lengthOfLIS(vector<int>& nums) {
        //LIS[i] = subsequenceの最後がnumsのi番目の時のLIS 最低1は保証される
        std::vector<int> LIS(nums.size(), 1);
        for (int i = 0; i < nums.size(); i++) {
            for (int j = 0; j < i; j++) {
                if (nums[i] > nums[j]) {
                    LIS[i] = std::max(LIS[i], LIS[j] + 1);
                }
            }
        }
        return *std::max_element(LIS.begin(), LIS.end());
    }
};
```
- 些細だけど、このコードのif (nums[i] > nums[j]) の箇所をcontinueしてネストを浅くする必要はあるだろうか
    - 「テレビが消えているなら、何もしないでください、そうじゃないなら消してください」より「テレビがついているなら消してください」の方が素直では

ニ分探索をする方法
- イメージ
    - DP[i][j] = numsのi番目まで使用して、subsequenceの長さがjの時の、subsequenceの末尾の最小値(これはjについて昇順)
        - i からi+1に遷移する時、更新する箇所は1箇所だけ(DP[i]の中で、nums[i]以上の値が初めて出てくる箇所)
        - これを二分探索で探す
```cpp
#include <algorithm>
#include <vector>

class Solution {
public:
    int lengthOfLIS(vector<int>& nums) {
        std::vector<int> LIS_elements;
        for (int i = 0; i < nums.size(); i++) {
            auto maybe_update_point = std::lower_bound(LIS_elements.begin(), 
                                                       LIS_elements.end(), nums[i]);
            if (maybe_update_point < LIS_elements.end()) {
                *maybe_update_point = nums[i];
            } else {
                LIS_elements.push_back(nums[i]);
            }
        }
        return LIS_elements.size();
    }
};
```

ニ分探索をする方法(番兵INT_MAXを使用して場合分けをなくす)
```cpp
#include <algorithm>
#include <climits>
#include <vector>

class Solution {
public:
    int lengthOfLIS(vector<int>& nums) {
        std::vector<int> LIS_elements(nums.size(), INT_MAX);
        for (int i = 0; i < nums.size(); i++) {
            auto maybe_update_point = std::lower_bound(LIS_elements.begin(), 
                                                       LIS_elements.end(), nums[i]);
            *maybe_update_point = nums[i];
        }
        //INT_MAXでないものの数が答え
        return std::lower_bound(LIS_elements.begin(), LIS_elements.end(), INT_MAX)
               - LIS_elements.begin();
    }
};
```

- セグメント木について(参考 https://tsutaj.hatenablog.com/entry/2017/03/29/204841　や https://www.slideshare.net/slideshow/ss-3578491/3578491)
    - 2分木の葉のノードに値を格納し、親ノードは子に対する演算結果（和、大小など）を格納することで、区間の最大最小、和などをlogNで取得することができるデータ構造のようだ
    - 値の更新は葉から根の方向に階層分更新していき、値の取得は根から葉の方向に辿っていくことで取得する
    - 対象区間が同階層では溢れたり足りなかったりする場合はその調整をする（ここが少しややこしいらしい）

- セグメント木イメージ
    - DP[i][j] = numsのi番目まで使用して、subsequenceがjという数字で終わるの時の、subsequenceの長さの最大値
        - i からi+1に遷移する時、DP[i+1][nums[i+1]]はDP[i]のindex[j]以下の最大値+1になる
        - DP[i]のindexがj以下の区間の最大値を高速で求めるために、セグメント木を使う

- 二分探索もセグメント木も、iからi+1に遷移した際、更新する箇所が固定されているのでin-placeに更新が可能なため、2次元配列は不要。1つの配列を更新していけば良くなっていると理解している。
